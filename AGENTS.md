# Repository Guidelines

Template developed by [Heartran](https://github.com/heartran)

## Project Structure & Module Organization

- Root-level Python tools:
  - `textTools-gui.py`: main Tkinter launcher for the desktop utilities, including OCR from clipboard.
  - `upperAllText.py`: clipboard monitor that converts copied text to uppercase.
  - `capitolAllText.py`: clipboard monitor that applies smart title casing for names.

- `requirements.txt`: shared runtime dependencies for clipboard monitoring, Windows APIs, and OCR support.

- `redist/tesseract-5.5.1` (if present): bundled Tesseract runtime used by the OCR flow in `textTools-gui.py`.

- `__pycache__/` is generated output. Do not edit generated bytecode files and do not commit cache artifacts unless explicitly requested.

## Build, Test, and Development Commands

- Create a virtual environment when needed: `python -m venv .venv`

- Activate it on PowerShell: `.\\.venv\\Scripts\\Activate.ps1`

- Install dependencies: `pip install -r requirements.txt`

- Launch the main desktop UI: `python textTools-gui.py`

- Launch the uppercase clipboard tool directly: `python upperAllText.py`

- Launch the smart title-case clipboard tool directly: `python capitolAllText.py`

- OCR support requires `pytesseract`, `Pillow`, and a working Tesseract binary either under `redist/tesseract-5.5.1`, in `Program Files\\Tesseract-OCR`, or available in `PATH`.

## Coding Style & Naming Conventions

- Follow Python conventions already used in the repo: 4-space indentation, snake_case for functions/variables, PascalCase for classes, and concise module-level globals only where the current design depends on them.

- Preserve the current app style: Tkinter-based desktop UI, straightforward script entry points via `main()`, and Windows-oriented integrations (`pywin32`, clipboard handling, process/window metadata).

- Keep user-facing copy and labels consistent with the existing language in each tool. When editing existing UI strings, prefer staying aligned with the repo's current Italian phrasing.

- Avoid broad refactors while touching a single tool. These scripts are small and stateful; favor localized changes that do not break clipboard loops, window lifecycle handling, or subprocess launch behavior.

## Testing Guidelines

- There is currently no automated test suite. Validate changes with targeted manual smoke tests on Windows.

- For `upperAllText.py` and `capitolAllText.py`, verify clipboard monitoring start-up, conversion behavior, pause/resume controls, and window shutdown.

- For `textTools-gui.py`, verify launcher buttons, single-instance lock behavior, subprocess launch of the child tools, and OCR behavior when dependencies are both present and missing.

- If you change OCR or runtime path detection, test at least one positive path and one fallback/error path.

## Commit & Pull Request Guidelines

- Use short, imperative commit messages (for example: `Fix OCR path detection`, `Add clipboard status refresh`).

- PRs should include intent, affected tool(s), and manual validation steps. Add screenshots only when UI changes materially.

- Keep changes scoped. If you touch multiple tools, the relation between them should be obvious from the commit or PR description.

- All commits should be done using **your own git identity**

- Do not work directly on `main`, `render/preview` or `railway/preview`: create a dedicated branch with setup prefix before committing or pushing.
  - Examples: `windsurf/feature-name`, `codex/fix-description`, `gemini/refactor-module`

- Never delete branches (no `--delete-branch` on merges) unless explicitly instructed.

- **Merge policy (MANDATORY for all agents): unless explicitly specified otherwise by the user, the merge target is ALWAYS `main`.**
  - If the target branch is not written clearly in the request, assume `main`.
  - Do not infer a different merge target from recent context/history.

## Identity & Git Hygiene

- Author/committer identity is managed by the repo owner; do not change git config locally (no `git config` commands). Use the existing configuration as-is. Use $ENV variables for agent-specific commits.

- Never use the Heartran git identity for commits or pushes.

- Keep commits small and topical; prefer multiple commits over one large drop when touching orthogonal areas.

## Windows & Packaging Notes

- This repository is Windows-first. Do not introduce Linux/macOS-only assumptions into runtime code or developer instructions unless explicitly requested.

- `textTools-gui.py` contains logic for both normal Python execution and packaged execution via `sys._MEIPASS`. Preserve that behavior when changing resource lookup or bundled asset paths.

- When changing dependency detection, prefer additive fallbacks over replacing existing path checks. The current tool supports bundled binaries, environment-variable overrides, and common installation paths.
